# OmniAgent OS: Full-Stack Autonomous Multimodal Desktop Agent & OS Controller

### Master Specification, Modular Blueprint & Antigravity Autonomous Execution Contract

## 1. Project Overview & Mandatory Sandboxing Constraints

You are an autonomous principal software engineer, systems architect, and OS automation specialist. You are strictly tasked with building the complete, production-grade source code for **OmniAgent OS** inside this specific project folder.

OmniAgent OS is an agentic desktop workspace that can operate both inside its own IDE workspace AND control the user's entire operating system (launching, reading, and interacting with external desktop software such as **Visual Studio, SQL Server Management Studio (SSMS), Terminal, Browsers, and Database engines**).

### CRITICAL SANDBOXING & SAFETY RULES (Zero-Pollution Contract)

1. **Strict Directory Isolation (Portable & Self-Contained):**
   * **ALL** application code, node modules, virtual environments, configuration files, cache, vector embeddings, and temporary screen captures **MUST** reside strictly inside this workspace root directory (`./`).
   * **DO NOT** execute global package installations (`npm i -g`, global pip install).
   * **DO NOT** touch or modify any path outside this folder, including system directories (`C:\Windows`, `C:\Program Files`, `~/.bashrc`, user profile roots), **EXCEPT** when explicitly instructed by the user to automate an installed desktop application (e.g., launching Visual Studio via system PATH).
   * Python runtime must use an isolated virtual environment located strictly in `./.venv/`.
   * Node runtime must use local dependencies located strictly in `./frontend/node_modules/`.

2. **System Safety & Mandatory Confirmation Protocols (Human-in-the-Loop):**
   * **NEVER** execute dangerous, irreversible, or harmful commands without explicit user permission.
   * **Harmful / Dangerous Action Classification:**
     * **Filesystem:** Deletion commands (`rm -rf`, `del /f /s /q`), disk partition tools, modifying OS registry hives (`reg add`, `reg delete`), altering Windows hosts file or system drivers.
     * **Database / SQL:** Destructive DDL/DML statements (`DROP DATABASE`, `DROP TABLE`, `TRUNCATE`, `ALTER TABLE` drops, unconditional `DELETE FROM` without `WHERE`).
     * **Network / Security:** Altering firewall rules, downloading unverified executable files from unknown endpoints.
   * **Confirmation Interceptor Rule:** Whenever any of the above operations are generated by the reasoning engine, the system must **HALT execution**, generate a visual confirmation card in the UI showing the exact action, command, and risk severity, and wait for the user to click **"ALLOW"** or **"DENY"**.

3. **Autonomous End-to-End Delivery:**
   * **NO** placeholders, no pseudo-code, and no `// TODO: implement later` comments.
   * Provide production-ready, fully working files for both frontend and backend.
   * The user will not write code manually. Everything must work out-of-the-box via local setup scripts.

### Master Module 1: Presentation & Workspace UI/UX Layer (`./frontend/`)
* **Sub-Module 1.1: Activity & Navigation Bar (`ActivityBar.tsx`):** Navigation for Workspace Code, External OS Control View, Terminal Farm, Visual AI Logs, and Settings.
* **Sub-Module 1.2: File Tree & Project Explorer (`FileExplorer.tsx`):** Real-time directory navigation, live diff highlights, git status, and workspace watch daemon.
* **Sub-Module 1.3: Multi-Tab Monaco Editor (`MonacoEditor.tsx`):** Dark-themed syntax-highlighted editor with side-by-side diff comparisons for suggested patches.
* **Sub-Module 1.4: Integrated Terminal Multiplexer (`TerminalView.tsx`):** Real-time xterm.js instance hooked directly to native background PTY (PowerShell / Bash).
* **Sub-Module 1.5: Conversational HUD & Approval Gatekeeper (`AgentChat.tsx`):** 
  * Displays agent reasoning, tool call histories, and visual screenshots.
  * **Interactive Confirmation Modal:** Pops up whenever a destructive command (SQL Drop, disk delete, registry change) is requested, providing full visibility and a 1-click Approve/Deny response.
* **Sub-Module 1.6: Ambient Status Bar (`StatusBar.tsx`):** Active provider, token counts, local Ollama connectivity, and OS Automation state.

### Master Module 2: Multi-Provider Model Ingestion Gateway (`./backend/gateway/`)
* **Sub-Module 2.1: Unified Provider Switchboard (`provider_gateway.py`):**
  * Seamless support for OpenRouter, Anthropic Native (Claude 3.5 Sonnet), OpenAI Native (GPT-4o, o3-mini), xAI Native (Grok 2 / Grok 3), and Local Offline LLMs (Ollama / vLLM / LM Studio).
* **Sub-Module 2.2: Dynamic Failover & Model Switcher (`fallback_router.py`):**
  * Automatically switches to offline Ollama models if API keys expire or network connectivity drops.
* **Sub-Module 2.3: Token Optimizer & Context Trimmer (`context_trimmer.py`):**
  * Compresses historical context and screenshot payloads to keep latency low.
* **Sub-Module 2.4: Local Secret Vault (`vault.py`):**
  * Stores API keys securely in a local `.env.local` file inside the workspace folder.

### Master Module 3: Agentic Reasoning & Computer-Use Engine (`./backend/agent/`)
* **Sub-Module 3.1: ReAct Orchestrator & Computer-Use Loop (`orchestrator.py`):**
  * Coordinates multi-step workflows: `[Receive Goal] -> [Observe Screen/Window] -> [Think] -> [Dispatch App Action / Tool] -> [Verify Feedback]`.
* **Sub-Module 3.2: Universal Application Controller (`app_orchestrator.py`):**
  * Manages interactions with external desktop applications:
    * **Visual Studio / VS Code:** Opening solutions (`.sln`), triggering builds (`Ctrl+Shift+B`), navigating error lists, opening specific files.
    * **SQL Server Management Studio (SSMS) / DBeaver:** Launching connection windows, pasting SQL scripts into query tabs, executing queries (`F5` or `Ctrl+E`), reading results or query execution errors.
    * **Web Browsers & Office Tools:** Launching, navigating, and inspecting UI structures.
* **Sub-Module 3.3: Targeted AST Patcher (`patcher.py`):**
  * Executes targeted chunk replacements for clean, incremental code updates.
* **Sub-Module 3.4: Master System Prompt (`system_prompt.py`):**
  * Enforces rigorous safety rules, structured tool calling, and OS automation directives.

### Master Module 4: Multimodal Sensory Subsystem (`./backend/multimodal/`)
* **Sub-Module 4.1: Audio Streaming & Voice-Activity-Detection (VAD) (`vad_listener.py`):**
  * Offline microphone listener detecting speech start and end automatically.
* **Sub-Module 4.2: Local Speech-to-Text (STT) (`stt.py`):**
  * Offline voice recognition powered by `faster-whisper`.
* **Sub-Module 4.3: Local Text-to-Speech (TTS) (`tts.py`):**
  * Offline voice audio feedback using `pyttsx3` or streaming Kokoro engine.
* **Sub-Module 4.4: High-Performance Screen Capture (`screen_capture.py`):**
  * Multi-monitor high-resolution screenshot grabber using `mss` or `Pillow.ImageGrab`.
* **Sub-Module 4.5: Visual Coordinate Normalizer (`coordinate_mapper.py`):**
  * Converts normalized coordinates ($0$ to $1000$) to exact pixel coordinates across varied screen scalings and monitor setups.

### Master Module 5: Full OS & External Software Automation Plane (`./backend/os_control/`)
* **Sub-Module 5.1: Desktop App Lifecycle & Window Manager (`window_manager.py`):**
  * Enumerate running processes and top-level windows.
  * Bring target windows (e.g., "Microsoft Visual Studio", "SQL Server Management Studio") to foreground focus before executing actions.
  * Launch executables from system PATH or standard installation locations.
* **Sub-Module 5.2: Accessibility & UI Element Inspector (`ui_automation.py`):**
  * Uses Windows UI Automation / `pywinauto` to locate elements by Name, ControlType, or AutomationId (e.g., click the SSMS "Execute" button directly, or focus the SQL Query Text Area).
* **Sub-Module 5.3: Mouse, Keyboard & Hotkey Synthesizer (`gui_controller.py`):**
  * Full synthetic input via `pyautogui` with safety fail-safes: mouse movement, single/double/right clicks, dragging, typing text, and sending IDE hotkeys (`F5`, `Ctrl+Shift+B`, `Ctrl+S`, `Ctrl+K, Ctrl+C`).
* **Sub-Module 5.4: Sandboxed Filesystem Tools (`file_tools.py`):**
  * Safe local file reading, writing, directory listing, and code search.
* **Sub-Module 5.5: Pseudo-Terminal (PTY) Shell Runner (`shell_runner.py`):**
  * Executes background commands with real-time stdout/stderr capture and strict timeout controls.

### Master Module 6: Safety, Sandbox & Audit Fabric (`./backend/safety/`)
* **Sub-Module 6.1: Destructive Command & Query Interceptor (`guardrails.py`):**
  * Inspects all commands and code before execution.
  * Flags destructive shell commands (`rmdir /s`, `format`, `del /s /q`).
  * Flags destructive SQL statements (`DROP DATABASE`, `DROP TABLE`, `TRUNCATE`, `ALTER TABLE ... DROP`).
* **Sub-Module 6.2: User Approval Gate Bridge (`approval_bridge.py`):**
  * Pauses the agentic loop whenever a high-risk action is detected and emits a WebSocket event to the frontend for human confirmation.
* **Sub-Module 6.3: Global Emergency Kill Switch:**
  * Background listener for `Ctrl + Esc` to immediately freeze all automated mouse/keyboard actions and terminate active subshells.
* **Sub-Module 6.4: Audit Journal (`audit_logger.py`):**
  * Chronological log file (`./workspace_audit.log`) recording every prompt, tool execution, and user confirmation.
